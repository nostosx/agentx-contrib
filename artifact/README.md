# Artifact storage (unreleased)

`artifact.S3` implements the core `agentx/artifact.Store` using an existing
`servex-contrib/storage/s3.Store`. It creates no SDK client, credential chain,
retry engine or HTTP transport. The application configures and owns those
dependencies. File storage is `filestore.Artifacts(dir)` in the independent
filestore module.

Core contracts remain provider-neutral. Scopes are trusted application identity;
never use a model-supplied tenant/user identifier without authorization.

```go
store, err := artifactstorage.NewS3(objectStore, artifactstorage.S3Options{
    MaxBytes: 64 << 20,
})
if err != nil { return err }
value := &artifact.Artifact{
    Scope: "tenant-42/user-7", ID: "image-123", Name: "generated.png",
    MediaType: "image/png", Data: generatedPNG,
    Metadata: map[string]string{"model": "gpt-image-2.5-flare"},
}
if err := store.Put(ctx, value); err != nil { return err }
saved, err := store.Get(ctx, value.Key)
if err != nil { return err }
_ = saved.Data
```

This assembly fragment imports the core `artifact` package and this module as
`artifactstorage`. `objectStore` is an application-configured servex S3 Store,
`generatedPNG` contains the generated bytes and `ctx` has a caller-owned deadline.

Each artifact is one JSON object containing bytes and metadata. This gives one
atomic replacement rather than a non-atomic pair of media/metadata objects.
S3 URLs identify the JSON envelope, not a raw PNG. Serve authorized media through
the application; this adapter does not issue media download links. There is no
implicit public upload, version history, indexing or deletion of old artifacts.
Choose a fresh ID for immutable revisions. Put replaces an existing scoped key;
Delete is idempotent. Scope/ID pairs are hashed without interpreting path syntax.

MaxBytes defaults to 64 MiB and may be 1 byte through 256 MiB. Envelopes have
an additional bounded metadata budget. SDK errors retain their chain; missing
objects become `artifact.ErrNotFound`. The app owns encryption, access policy,
quotas and the S3 Store/SDK client's lifetime.

## Agent integration

Both S3 and file storage can be supplied to `imagegen.ToolOptions`:

```go
imageTool := imagegen.Tool(images, imagegen.ToolOptions{
    Artifacts: store, ArtifactScope: "tenant-42/user-7",
    ResolveImage: func(ctx context.Context, id string) (model.Part, error) {
        value, err := store.Get(ctx, artifact.Key{Scope: "tenant-42/user-7", ID: id})
        if err != nil { return model.Part{}, err }
        return model.ImagePart(value.MediaType, value.Data), nil
    },
})
```

Generated image bytes remain in result Parts; `Metadata["artifacts"]` holds
the saved scoped references. Scope comes from configuration, not tool arguments.
Persistence uses fresh UUIDs. A failure returns `*imagegen.ArtifactError`, which
retains the generated Response, already-saved keys and the storage error. Do
not regenerate merely to retry persistence. Several artifact writes are not
a transaction; successful earlier writes remain available.

## Development and release

The module requires the matching unreleased core artifact contract and
unreleased servex S3 adapter. The zero pseudo-version in go.mod is an explicit
development placeholder, not a published release. Use an external Go workspace
or temporary modfile resolving those sources. No local replacements belong in
repository manifests. Release core and the servex S3 foundation first, update
requirements/checksums, then verify independent public consumers.

For a workspace outside these repositories, include the three source modules
and replace the exact unpublished foundation version in that workspace:

```sh
go work init /absolute/path/to/agentx /absolute/path/to/agentx-contrib/artifact /absolute/path/to/servex-contrib/storage/s3
go work edit -replace=github.com/nostosx/servex-contrib/storage/s3@v0.0.0-00010101000000-000000000000=/absolute/path/to/servex-contrib/storage/s3
```

Task forces GOWORK=off; for Task gates use external temporary module files
instead. None of these development overrides establishes public availability.

`task check MODULES=artifact`, `task lint MODULES=artifact` and
`task vulncheck MODULES=artifact` use the repository's standard gates, with
external development overrides while peers are unpublished. Tests exercise
the real AWS SDK and servex adapter against a local HTTP fixture and run the
core artifact conformance suite, including scoped identity and concurrent
replacement. They do not prove live AWS or arbitrary S3-service compatibility.
